# Acceptance criteria: Example conversation activity

- Frozen at: 2026-10-02

## Criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-001 | When the session's start call returns without throwing while the epoch recorded before the call is still current and the controller still holds the same session, the controller shall set status to the sentence beginning "Listening. Say" and containing “hello”, “what is your name?” and “thank you”, set displayedActivity to TurnActivity.listening, and set activityPaused to false. | Controller test: drive initialize and download-and-prepare to a ready fake session, call start, complete the fake's start completer, then read status, displayedActivity and activityPaused. | A test that asserts status is unchanged after a successful in-epoch start fails, proving the sentence is written rather than skipped. |
| AC-002 | When the capture flag is true and a non-fault event arrives with activity speaking, the controller shall set status to exactly "Speaking the reply. Listening is paused." and set displayedActivity to TurnActivity.speaking. | Controller test: reach a successful start, add a state event with activity speaking to the fake session's event stream, flush, then read status and displayedActivity. | The same event delivered before start succeeds leaves status and displayedActivity untouched, so the status is gated on capture and not on event arrival. |
| AC-003 | When the capture flag is true and a non-fault event arrives with activity recognizing, thinking, interrupting or idle, the controller shall set status to exactly "Hearing you.", "Preparing a reply.", "Interrupting." or "Waiting for speech." respectively and set displayedActivity to that activity. | Controller test: one case per activity value on a started session, asserting the exact sentence and the matching displayedActivity. | A status that contains the activity enum name, for example the bare word "recognizing" as the whole message, fails the exact-string assertion. |
| AC-004 | When the capture flag is true and an event arrives whose lifecycle is suspended, the controller shall set status to exactly "Paused by the system. Tap Start when you want to continue.", set displayedActivity to TurnActivity.idle, set activityPaused to true, and clear the capture flag so that a following listening event does not change status. | Controller test: reach a successful start, add an event with lifecycle suspended, flush, read status, displayedActivity and activityPaused, then add a listening event and assert status is still the paused sentence. | A listening event delivered after the suspended event replaces the paused sentence, which fails the second assertion. |
| AC-005 | When stop has completed on a current epoch and the same session, and a non-fault event with activity listening then arrives, the controller shall leave status at "Stopped. Tap Start when you want to continue." and leave displayedActivity at TurnActivity.idle. | Controller test: start, complete start, stop, then add a listening event, flush and read status and displayedActivity. | An event that moves status away from the stopped sentence or moves displayedActivity away from idle fails, proving events are ignored after stop. |
| AC-006 | When an event carries a non-null failure, the controller shall set status to exactly "The on-device speech engine reported a problem. Stop and retry.", set phase to ExampleSetupPhase.failed, set displayedActivity to TurnActivity.idle, set activityPaused to false, and clear the capture flag so that a following listening event does not change status. | Controller test: reach a successful start, add a fault event, flush, read status, phase, displayedActivity and activityPaused, then add a listening event and assert status is still the fault sentence. | A listening event delivered after the fault event replaces the fault sentence, which fails the second assertion. |
| AC-007 | When a non-fault event arrives after setup has created the session but before any start call has succeeded, the controller shall leave status at the setup text that contains "Ready", leave displayedActivity at TurnActivity.idle and leave activityPaused false. | Controller test: drive initialize and download-and-prepare to a ready fake session, add a listening event, flush, then read status, displayedActivity and activityPaused. | The status changes to an activity sentence, which fails the assertion and shows the capture gate is absent. |
| AC-008 | When a non-fault event with activity listening is handled while the capture flag is true, the resulting status shall not contain a lifecycle enum name followed by a middle dot and an activity enum name. | Controller test: after a successful start, add a listening event, then assert the status contains the listening sentence and does not match the lifecycle-dot-activity shape for any lifecycle and activity name pair used in the event. | A status equal to the lifecycle name joined to the activity name by a middle dot fails this assertion. |
| AC-009 | When displayedActivity is TurnActivity.speaking and activityPaused is false, the screen shall render a widget keyed activity-indicator whose visible text is "Speaking" and whose semantics label contains "Speaking". | Widget test: pump the screen with a controller whose fields are in that state, find the widget by key, and assert the text and the semantics label. | A screen that renders no widget keyed activity-indicator, or renders the activity enum name instead of the short label, fails the find or the text assertion. |
| AC-010 | When activityPaused is true, the activity indicator shall show the label "Paused", and when displayedActivity is TurnActivity.idle and activityPaused is false, it shall show the label "Idle". | Widget test: two pumps of the screen, one per state, asserting the indicator text in each. | The indicator shows "Idle" while activityPaused is true, or shows "Paused" before any start, which fails the matching assertion. |
| AC-011 | When the screen is pumped before setup has produced a session, the widget keyed start-button shall still be a FilledButton whose onPressed is null, and the widgets keyed interrupt-button and stop-button shall still be present. | Keep and extend the existing assertion in example/test/voice_screen_test.dart that reads the FilledButton by key; add finds for the other two keys. | A start-button that is no longer a FilledButton, or whose onPressed is non-null before setup, fails the existing test. |
| AC-012 | When the app goes to the background while a start call is still in flight and that call later completes, the controller shall leave status containing "background" and shall not set the capture flag, so a following listening event does not change status. | Keep the existing late-start-after-background controller test and extend it to add a listening event after the start future completes, then assert status still contains "background". | A status that no longer contains "background", or an activity sentence appearing after the stale start, fails the test. |
| AC-013 | When the app resumes while a session exists and the phase is ready, the controller shall leave status containing "Ready" and leave displayedActivity at TurnActivity.idle. | Keep the existing background-and-resume controller test and add the displayedActivity assertion. | A status that no longer contains "Ready" fails the existing assertion. |
| AC-014 | When available storage is below the required amount on the download path, the controller shall still produce a status containing "Not enough free space". | Keep the existing insufficient-space controller test unchanged. | Removing or weakening that substring fails the existing test. |
| AC-015 | When the session's interrupt call returns without throwing on a current epoch and the same session, the controller shall set status to the same sentence beginning "Listening. Say" used after start, set displayedActivity to TurnActivity.listening, and leave the capture flag set so that a following speaking event still writes its sentence. | Controller test: reach a successful start, call interrupt, await it, read status and displayedActivity, then add a speaking event and assert the speaking sentence appears. | A speaking event that fails to change status after interrupt shows interrupt cleared the capture flag, which fails the second assertion. |
| AC-016 | When stop returns without throwing on a current epoch and the same session, the controller shall set status to exactly "Stopped. Tap Start when you want to continue.", set displayedActivity to TurnActivity.idle and set activityPaused to false. | Controller test: start, complete start, stop, then read status, displayedActivity and activityPaused. | A stopped status that still reports an active activity, or a displayedActivity other than idle, fails the assertion. |
| AC-017 | When the repository is inspected after this change, the ExampleVoiceSession interface shall still declare exactly events, start, interrupt, stop, dispose and setSpeakerId, and no file under lib/ shall be modified. | Read the interface declaration in example/lib/voice_screen_controller.dart and run a diff of lib/ against the base commit. | A new interface member, or any diff hunk under lib/, fails this check. |
| AC-018 | When the screen is pumped, the status text shall remain a Text keyed status inside a Semantics node with liveRegion true, and the static sentences containing "English voice model", "Files, sources, and licenses", "Three English options", "VCTK is a speaker choice", "fixed demo rules" and "Listening pauses while a reply plays" shall all still be findable. | Keep the existing widget-test finds and add a find for the live-region status node and for the sentence about listening pausing while a reply plays. | A removed or reworded static sentence, or a status text outside the live region, fails the find. |

## Non-functional criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-019 | When example/lib/main.dart and example/lib/voice_screen_controller.dart are searched, the phrases "full duplex", "barge-in" and "wake word" shall be absent from new copy, and no new sentence shall claim accuracy, measured quality or production readiness. | Case-insensitive search of both files for the three phrases; read every new or changed user-facing string. | Any of the three phrases, or a new sentence promising quality or production readiness, fails the search or the read. |
| AC-020 | When the activity indicator is rendered, its state shall be conveyed by an icon and a text label with a matching semantics label, and shall not be conveyed by colour alone. | Read the indicator widget; widget test asserts both an Icon and the label text inside the node keyed activity-indicator. | An indicator built from a coloured dot with no text and no semantics label fails the widget test. |
| AC-021 | When the repository checks are run, dart format over lib and example/lib shall report no file changed, dart analyze with fatal infos and fatal warnings shall exit 0, the example test suite shall pass, and tool/lint_wiki.py shall report clean. | Run the four commands and paste their output into the verification artifact. | A passing claim with no pasted output, or a non-zero exit from any of the four, fails this criterion. |

## Explicitly not required

- Any change under `lib/`, including a library event emitted when start succeeds.
- A new member on `ExampleVoiceSession` or on the test fake.
- A single microphone control, or any change to the Start, Interrupt and Stop enablement rules.
- A short label rendered for the idle activity other than "Idle"; the word "Waiting" appears in the idle status sentence, not on the indicator.
- Establishing which activity values each native host or the web backend actually sends, or in which order. The two unresolved research questions stay unresolved.
- Colour, theme or layout redesign beyond inserting one indicator into the existing conversation controls.
- Localisation, or any non-English copy.
- Edits to `README.md`, `doc/capabilities.md` or wiki product pages. Documentation belongs to the later document phase.
- A status write for a non-fault event while the capture flag is false, including a suspended lifecycle arriving before start succeeds.
